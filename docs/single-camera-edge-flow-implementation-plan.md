# 单相机抓边流程复刻实施方案

日期：2026-10-19  
状态：实施方案，尚未开始代码实现

目标是在 ComputerVisionFlow 中按用户提供的海康流程照片，复刻完整业务节点、纵向布局、分支和汇合；复用 Demo_Wafer_Locator 的算法生成定位图像与坐标。设备动作和未实现的检测环节保留在画布中，以明确的模拟或未验证状态运行，不将流程缩减为图片加载、定位、显示几个节点。

首版交付是一份可以打开、运行、保存和恢复的完整演示工程，以及可检查的定位图像、测量结果和模拟发送记录。真实设备控制、海康模块算法等价、物理坐标精度和碎片检测精度不作为首版完成条件。

## 1 实施范围与固定原则

1. 按原图保留业务节点，不用大模块替代四角、测量、尺寸、缺陷和结果输出分支。
2. 原图编号用于展示和追溯，不作为运行时节点 ID。复制节点时分配新的运行 ID，并保留来源编号。
3. 原名称、拓扑、节点内部算法是三类独立信息。照片能够支持的节点及连线按照片复刻；看不清的名称、输入绑定和判断条件记录为待核对项。
4. Demo 算法只在“62 进入流程”中对每次运行调用一次。下游节点读取角点、计算几何量和组织结果，不重复执行整套定位。
5. 使用现有 DSPatch 执行机制、QtNodes 编辑器和插件接口，不另建通用工作流引擎。
6. 首版专用演示配置使用单缓冲、单次触发，一次只处理一个工件。节点采用 InOrder；这不等于全图串行，仍须对 GUI 与计算线程共享状态加锁。
7. 首版只有模拟设备适配器，没有真实电机、光源、串口或网络发送动作。发送界面明确标注坐标空间和单位。
8. 原图结构复刻与算法验证分别验收。运行成功不能代替原图连线核对；画布完整也不能代替结果检查。

## 3 定位算法复用

当前代码入口为 plugins/IndustrialDemo/demo_wafer_locator.cpp。其端口为 in/CvMat、out/CvMat、pose/JSON，成功时返回 center、angle_deg、corners 和 area_px2；异常时返回 success=false 与 status。

新增 wafer_locator_algorithm.hpp/.cpp，将算法与 DSPatch 节点包装分离，接口建议为：

```cpp
WaferLocationResult LocateWafer(const cv::Mat& image,
                               const WaferLocatorOptions& options);
```

结果对象包含有效性、错误信息、四角、中心、角度及标注图。原 Demo 节点继续保留原名称、端口、参数与 JSON 字段，通过适配调用共享函数。进入流程节点调用同一算法，不通过创建另一条隐藏图来重复执行 Demo。

首次提取保持原行为，用测试固定结果；算法调整单独实施。现有 right_limit_ratio、bottom_limit_ratio 以及至少 50 个内点等条件针对特定图像，需要用实际样本核对。不得为“让示例通过”而掩盖定位失败。

单次运行开始时冻结算法参数；运行中修改参数在下一次触发生效。相同 session_id/run_id 的重复 Tick 复用本次结果，缓存同样包含失败结果，防止持续重试和重复副作用。

## 4 数据接口与执行规则

### 4.1 上下文结构

业务节点使用现有 JSON 端口承载流程上下文；图像使用 CvMat 端口，不把像素编码进 JSON。下面是失败或尚未计算时也可以传递的结构：

```json
{
  "schema": "visionflow.single_camera_edge.v1",
  "session_id": "runtime-session-id",
  "run_id": 1,
  "frame_id": 1,
  "mode": "demo",
  "coordinate_space": "image",
  "unit": "pixel",
  "step": {
    "key": "entry_62",
    "state": "pending",
    "message": ""
  },
  "pose": {
    "valid": false,
    "center": null,
    "angle_deg": null,
    "corners": null
  },
  "measurements": {},
  "checks": {
    "location": "unknown",
    "size": "unknown",
    "fragment": "unknown"
  },
  "verdict": {
    "demo": "unknown",
    "business": "unknown"
  },
  "steps": {}
}
```

step.state 取 pending、done、simulated、skipped、unverified、failed；checks 与 verdict 取 pass、fail、unknown。运行状态与业务判断分开，模拟完成不等于检测通过。步骤记录以工程内唯一 step_key 索引，不能只用原图编号，避免复制节点后冲突。

角点顺序固定为左上、右上、右下、左下，字段中记录此约定。定位失败时坐标置 null，不使用上一轮坐标或零坐标替代失败。

### 4.2 端口契约

| 节点类别 | 输入 | 输出 |
| --- | --- | --- |
| 运行起点 | 用户触发命令 | flow/JSON |
| 模拟设备、透传、几何处理 | flow/JSON | flow/JSON |
| 相机 | flow/JSON | flow/JSON、image/CvMat |
| 校正、采集完成、定位入口 | flow/JSON、image/CvMat | flow/JSON、image/CvMat；入口另有 overlay/CvMat |
| 汇合 | 固定数量的 flow_0…flow_n/JSON | flow/JSON |
| 分支 | flow/JSON | ok/JSON、ng/JSON |
| 图像处理 | flow/JSON、image/CvMat | flow/JSON、image/CvMat |
| 最终渲染 | flow/JSON、image/CvMat | flow/JSON、image/CvMat |

不同节点类别固定端口数量和类型，参数编辑不动态改变端口结构。若需要两路与四路汇合，注册两个固定类型，共用实现。相机到定位入口的图像和上下文必须由同一轮处理成对产生、成对透传；禁止读取一个未绑定运行编号的全局“最新图像”。

首版冻结单次图像、单缓冲并禁止运行重入。定位入口只在同一 SignalBus 处理轮次取得完整配对输入时运行；缺图像返回明确失败。该配对假设必须通过阶段 S0 的实际 DSPatch 测试。多缓冲和视频连续处理不沿用未经验证的配对规则。

### 4.3 触发与分支

- 在首节点 Controls 中提供加载样本配置、运行一次、清除结果。运行按钮只登记请求，由处理线程消费；会话运行中禁止重复触发。
- 同一次运行允许重复传播不可变输入快照，以适应 AutoTick；每个节点按 session_id/run_id 缓存处理结果。模拟发送、保存和日志只执行一次。
- 修改工程、重新加载或清除结果时更换 session_id，清空运行缓存和状态。运行结果不写入工程参数。
- 分支的两个输出每轮都有状态：选中分支携带活动上下文，未选中分支携带 skipped 上下文。收到 skipped 的普通节点不计算、不执行副作用，只继续传播 skipped。
- 不通过节点 SetEnabled(false) 表示业务分支未选中；不同现有节点的禁用语义不一致。
- 合流检查 session_id/run_id/frame_id。编号不同则报告失配，不跨轮合并；各分支只写自己的字段，重复公共字段值不一致时报错，不静默覆盖。
- 执行错误也必须形成结果上下文，不能靠“无输出”表示失败。缺少必需输入时有明确等待状态和超时，不能永久等待；首版超时由演示会话协调器监测，默认 10 秒、可配置。
- 会话协调器仅负责运行编号、触发、超时与观察终点完成，不替代 DSPatch 调度，不在画布上增加反馈环。

### 4.4 OK 和 NG 语义

首版采用演示判定：定位有效且所有已启用的真实检查通过时，demo=pass；任一已启用检查失败时为 fail；必需检查无结果时为 unknown。unknown 进入 NG 支路并携带“待验证”原因，不显示为已证实的不良品。

business 只有在标定、尺寸和碎片等规定业务检查均完成且通过后才能为 pass。首版缺陷检测未实现，所以 business 保持 unknown。界面显示“演示 OK，业务待验证”或对应失败信息。

成功、尺寸失败和定位失败用实际输入与阈值产生测试路径；可以在测试夹具中注入结果验证支路，但演示工程不得用隐藏的强制成功参数生成合格图像。

## 5 几何计算与图像输出

### 5.1 几何定义

设四角为 P0、P1、P2、P3：

- 上、下、左、右边长分别为 |P1-P0|、|P2-P3|、|P3-P0|、|P2-P1|，单位 pixel。
- 第一条中线连接上、下边中点，第二条中线连接左、右边中点。两条中线的方向及名称绑定显式配置。
- Demo 原中心是两条对角线交点。中线交点与它在一般四边形上不一定一致；保留 locator_center 和 midline_center 两个字段，首版发送取 locator_center，不能悄悄替换。
- Demo 角度为 P0→P1 的图像方向角。图像 Y 轴向下，设备旋转正方向未知；设备角度转换待标定。
- 线线测量以“指定两条线的夹角”为首版演示模式，注明角度范围；相交线不能以任意单一值冒充平行线距离。
- 面积字段 area_px2 是选中连通区域的像素数，不等同于拟合四边形面积；需要后者时另建字段。
- 尺寸阈值为空时返回 unknown。长度非有限、角点无效或线退化时明确失败。

### 5.2 三个观察窗口

原图业务节点不被 Viewer 替代；在右侧观察区增加原图 Viewer、定位 Viewer 和最终结果 Viewer。辅助节点属于展示区域，原图编号留空。

原图 Viewer 显示输入快照；定位 Viewer 显示 Demo 的四角、边线、中心和角度；最终 Viewer 增加像素尺寸、定位状态、尺寸检查状态、碎片待验证状态和当前运行编号。失败时显示本次原图及失败原因，清除旧的成功覆盖信息。

保存提供两种明确动作：使用 Image_Writer 手动保存选定图像；使用演示导出按钮保存同一运行的 original.png、located.png、result.png、result.json 和模拟发送日志。导出以 session_id/run_id 建子目录，避免覆盖其它运行；失败运行也允许导出。Image_Writer 的原有路径与状态契约保持不变。

## 6 画布与工程保存

以照片中的纵向结构为主，中间为定位及坐标主线，左侧为尺寸分支，右侧为图像与碎片分支，底部为发送和 OK/NG。四角和发送 X/Y/R 横向排列。

首版优先复刻业务框架和位置，不重写 QtNodes 以追求每个箭头及模块外形的像素一致。长连线采用现有绘制能力，明确保留端口和方向；若交叉影响辨认，再局部改善路径。

GraphModel 增加 display_name、source_id、source_note 等可选编辑元数据。标题显示“原图编号 名称”，无元数据的旧节点继续显示原有标题。元数据保存在 .flow 的 editor 项中；组件类型名与运行 ID 不变。

保存恢复、子图复制、剪切、粘贴、删除和失败回滚都要处理这些字段，不能只改显示标题。状态颜色配合文字：完成、模拟、未验证、失败、跳过均可辨认；原有启用/禁用外观保持含义。GUI 通过只读快照定时刷新运行状态，不从计算线程直接操作 QWidget。

重新打开工程时恢复节点、位置、连接、显示名称和参数；运行状态恢复为未运行。图片路径相对演示工程目录解析，缺文件时报出完整定位信息，不复用缓存图像伪装加载成功。

使用少量固定类型、多实例和参数复用，不为照片里的每个方框复制一个 C++ 类。当前插件以单个 Create 入口创建组件，不能假设一个 .fp 自动注册多个节点类型；每种可创建类型使用独立目标和明确工厂，共用算法与辅助库。凡是需要跨插件共享的会话状态，必须由同一宿主服务实例持有，不通过各插件静态变量隐式共享。

工作区已有主题、GraphModel、Editor 和 Demo 的未提交修改。实施前记录相关差异，在现有基础上增量修改，不覆盖或回退这些改动。除必要的通用标题和状态支持，不在 MainWindow 中追加具体业务节点分支。

## 8 分阶段执行和完成条件

| 阶段 | 任务及交付 | 完成条件 |
| --- | --- | --- |
| S0 结构登记与调度验证 | 完整节点清单、layout.json；用小型测试图验证 JSON 与图像配对、双分支和汇合 | 照片中的可见方框逐一登记；待核对边显式标记；跳过、失败、失配和重复 Tick 测试有明确结果 |
| S1 原图完整画布 | 实现元数据、通用模拟/透传/汇合节点；生成全部业务节点和连线 | 完整图能够打开、保存和恢复；主线及各分支均存在；不是简化流程。此时尚无真实定位也可交付结构验收 |
| S2 定位算法接入 | 提取算法；完成相机、采集状态和“进入流程”；接入原图与定位 Viewer | 用户样本产生真实定位或明确失败；同一运行算法调用一次；原 Demo 接口回归通过 |
| S3 几何和判定 | 接入四角、点线测量、尺寸、中线、尺寸管控和结果汇合 | 每项数值可追溯至角点；失败不沿用旧值；未标定、未实现检查保持 unknown |
| S4 完整输出链 | 格式化、模拟发送、OK/NG 全部分支、最终渲染和导出 | 一次运行完整到达末端；未选分支显示跳过；坐标、图像和日志属于同一次运行 |
| S5 集成验收 | 原图结构核对、完整图回归、原生 UI 检查、演示说明 | 满足第 9 节；记录截图、结果文件及未核对项，不把模拟项计为实际业务通过 |

执行顺序为 S0 → S1 → S2 → S3 → S4 → S5。S0 的小型图只用于验证执行机制，最终交付和 S1 画布始终保留原图完整结构。先跑通调度约定再铺开节点，避免完成几十个节点后才发现分支不能汇合。

## 9 测试与验收

### 9.1 自动化检查

- 算法提取回归：固定输入与参数，对比原 Demo 的四角、中心、角度、状态及标注图；误差阈值说明来源。
- 算法异常：空图、输入类型不支持、前景缺失、边点不足、近乎平行拟合线；失败时不输出有效坐标。
- 样本适配：正常四边形、带突出遮挡的样本，以及默认比例可能错误过滤边缘的样本。实际精度用人工标注或独立参考值评估，不只比较算法自身输出。
- 调度：同一 run 重复 Tick 不重复定位或发送；新 run 正常执行；会话重建不命中旧缓存。
- 分支汇合：两条分支均有消息、非活动支路 skipped、失败传播、字段冲突、运行编号失配和超时。
- 图像配对：交替运行两张明显不同的图片，结果图、JSON、发送日志保持对应；输入失败后不得显示上一轮成功坐标。
- 完整图：节点清单与工程一一对应，无遗漏、悬空必需输入或意外环；所有原图分支都有结束路径。
- 持久化：名称、来源编号、位置、参数与连线保存重开；子图复制重新生成运行 ID 和 step_key，运行状态不复制。
- 生命周期：运行中删除节点、替换工程、关闭窗口时协调器和 UI 释放正确，不访问已释放插件。

测试限定隔离文件和模拟适配器，不运行真实设备通信。已有简单节点不为此次文档方案补测试；实现阶段只增加上述有回归意义的检查。

### 9.2 构建与测试入口

在 Visual Studio x64 Developer PowerShell 中，使用当前已存在的本机预设：

```powershell
cmake --preset local-x64-release -DVISIONFLOW_BUILD_TESTS=ON
cmake --build --preset local-x64-release --parallel 4
ctest --test-dir out/build/local-x64-release -R '^industrial_' --output-on-failure
ctest --test-dir out/build/local-x64-release -R '^(graph_edit|studio|viewer)$' --output-on-failure
```

industrial_ 测试名为拟定命名，需先在实现阶段注册；当前执行这些命令不代表新功能已存在。涉及公共图状态变更时运行上述公共回归，检查通过后不无理由重跑无关硬件和 DNN 测试。

### 9.3 最终交付核对

- [ ] 原图每个可见节点均有登记，末端 OK/NG 子步骤没有被合并省略。
- [ ] 完整画布与参考图逐区核对；待核对标签和连线清单可查。
- [ ] 正常定位样本、定位失败样本、尺寸不合格样本均能完整结束。
- [ ] 模拟与未验证节点不显示为真实检测通过。
- [ ] 原图、定位图、最终图和 JSON 均能检查并导出。
- [ ] 单次运行没有重复计算、重复模拟发送或重复写文件。
- [ ] 保存重开后可以再次运行，缺失图片能清楚定位原因。
- [ ] 原 Demo 接口与已有普通工程保持可用。
- [ ] 用户实际样本上的坐标与标注经核对；没有样本时，只能交付合成图验证，实际样本验收仍未完成。

## 10 待补输入与默认处理

| 输入 | 未提供时的处理 | 影响 |
| --- | --- | --- |
| 相机原始工件图片，至少一张正常与一张失败样本 | 使用生成的测试图完成基础实现 | 不能完成实际场景效果验收 |
| 末端节点清晰截图或原工程节点清单 | 按可见方框逐个占位，标记待核对 | 不能宣称节点名称和连线完全确认 |
| 点点、线线、中线节点参数及输入绑定 | 使用第 2 节明确列出的演示绑定 | 保留结构，但不宣称复现海康测量语义 |
| 尺寸阈值 | 不默认判定合格，尺寸检查为 unknown | 可展示实际像素长度 |
| 相机标定、基准位置、设备旋转方向与发送协议 | 保持像素坐标和模拟发送 | 不输出可直接用于设备运动的补偿量 |

缺少上述信息不阻止 S0、S1 和基础实现。实际样本效果与精确原流程语义，在获得对应输入后完成核验；不能用等待时间或默认值代替确认。
