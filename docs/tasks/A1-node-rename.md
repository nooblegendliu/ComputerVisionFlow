# 目标

让用户能把 `Line_Intersections_1` 这样的默认标题改为“左上边缘交点”等业务名称，并把名称保存到工程中；同时保留节点类型、唯一实例标识、DSPatch 连接和插件机制不变。

# 开工前必须读取

1. `AGENTS.md`
2. `docs/plans/visionmaster-gap-analysis.md` 中 R-001
3. 当前仓库实际的 `VisionFlowGraphModel` 头/源文件、QtNodes 节点 Caption 相关实现
4. 节点右键菜单位置、工程序列化与反序列化实现、编辑器状态保存格式

以前的版本中 `VisionFlowGraphModel.cpp` 使用 `NodeRole::Caption` 返回“类型名 + 实例数”。该信息只用于代码检索定位，**不得跳过源码核对**。

# 工作范围（Scope）

- 新增“实例显示名”编辑器元数据；默认值遵循现有标题行为。
- 支持从节点右键菜单或现有适合的编辑控件执行 Rename。
- 按稳定节点实例 ID 存取显示名；不要把类型名或者节点指针当作持久化键。
- 复用现有 `.flow` 编辑器元数据保存/加载通道；加载旧文件时无新字段则正常使用默认标题。
- 若现有复制、粘贴、删除机制会影响名称映射，在现有逻辑中做最小必要维护。

# 明确不做（Non-goals）

- 不增加 DSPatch 节点、不改变 FlowCV Node 名称、插件查找、端口、计算链路。
- 不改第三方 QtNodes/DSPatch 代码。
- 不重构整个工程格式或编辑器模型。
- 不实现 Group/Comment；那是 A2。
- 不新增无关测试程序、调度机制或工业算法。

# 候选修改位置（不是强制路径）

| 候选文件 | 修改意图 |
|---|---|
| `editor/Graph/VisionFlowGraphModel.hpp` | 显示名称的内存数据、访问方式 |
| `editor/Graph/VisionFlowGraphModel.cpp` | Caption 读取、新值通知、清理映射 |
| `editor/VisionFlowEditor.cpp` | 节点 Rename 交互 |
| `app/VisionFlowStudio/MainWindow.cpp` | 仅当其承担现有工程 editor 状态聚合时，接入存取 |

如果代码组织不同，以当前仓库为准，且说明为什么偏离表中路径。

# 实施顺序

1. **源码审计**：画出“节点 ID → 标题显示 → context menu → editor 状态 JSON”的现有调用路径。
2. **兼容性设计**：确认现有 JSON 的哪一层可容纳纯 UI 元数据；明确旧工程缺字段的行为。
3. **最小实现**：新增显示名及 Rename 交互；在 title 更新后使用现有模型通知接口刷新。
4. **生命周期检查**：新建、删除、复制、粘贴、保存、重新加载的实例名称是否正确；不影响节点 ID 与连线。
5. **实际验证并汇报**：若无法编译，报告操作命令与原因，不能写“已通过”。

# 验收标准

- [ ] 不改名时显示与旧版本一致。
- [ ] 可将一个实例显示名修改为业务名称；其它同类型实例不受影响。
- [ ] 保存再打开后恢复该实例显示名；旧文件可打开。
- [ ] 类型名、端口、连接数、运行结果不因 Rename 改变。
- [ ] 删除/复制/粘贴后不产生悬挂映射或重复 ID 绑定（如现有操作支持）。
- [ ] Qt UI 层以外无与显示名无关的大规模改动。
