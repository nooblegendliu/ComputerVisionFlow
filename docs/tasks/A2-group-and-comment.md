# 目标

让复杂视觉流程拥有可读的分区框、标题和说明文本，在不改变 DSPatch 图结构的前提下组织 30–100 个节点的业务场景。

# 前置条件

- A1 已完成并验证。
- 当前仓库已有节点定位、平移缩放、视图保存恢复机制已查明。

# Scope

- 增加纯 UI 的 Group 视觉框（标题、矩形位置/大小，适当的中性底色）。
- 增加 Comment 文字注释（文字内容、位置）。
- 可创建、选中、编辑、删除，并能保存恢复。
- 分组背景不遮挡节点、端口与连线操作；明确绘制 Z-order 和事件接收行为。
- 复用现有 Qt 视图场景与 editor JSON 元数据；旧工程缺字段可正常加载。

# Non-goals

- Group 不等于 DSPatch 子图；暂不提供 group 内部独立执行、折叠后执行、跨组端口、自动布局。
- Comment 不是计算节点；不进入 FlowCV Manager、插件登记、端口定义。
- 不改第三方 QtNodes 库，除非充分证明扩展机制不能满足并经用户批准。
- 不做复杂的自动分组、嵌套 group/批量布局系统。

# 实施步骤

1. 查当前 QtNodes 图视图/场景暴露的扩展点，选择 UI 层最小实现方式。
2. 设计与现有 editor 元数据兼容的 group/comment 记录，必须与 node IDs/positions 分离。
3. 实现添加和删除 Group/Comment 的入口；确保绘制与交互不抢节点/连线事件。
4. 做保存、恢复、旧工程加载以及运行行为不变验证。

# 验收

- [ ] Group 和 Comment 仅为 UI 元数据，执行图节点数不因添加它们改变。
- [ ] 可编辑标题/注释、移动、删除；重新打开可恢复。
- [ ] 连线、拖动、节点选择不被背景元素挡住。
- [ ] 不影响旧工程兼容性。
