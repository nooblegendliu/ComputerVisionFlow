# 1. 目的

从用户提供的三张 VisionMaster 工程案例照片，提取**可证实的流程结构**，结合公开资料和 ComputerVisionFlow 已知架构，建立可追踪的需求清单。本文用于开发规划，不是对海康内部算法或完整执行机制的反向确认。

# 4. 关键概念边界

| 概念 | 含义 | 不应混淆为 |
|---|---|---|
| 数据分流 | 一个输出连接多个下游，允许数据被不同节点使用 | 条件分支 |
| 数据选择 | 多个已获得的数据结果按条件选择一个 | 未选分支不会执行 |
| 条件执行 | 根据条件决定是否执行某一条分支的计算任务 | `if` 形状连线/不输出图像 |
| 视觉 Group | 编辑器中的节点分区、说明性框架 | 计算子图/独立调度容器 |
| 工业结果 NG | 算法完成，但不满足检测条件 | 程序错误、异常或 skipped |
| 工业卡尺 | ROI、边缘极性、采样、精度/质量评估的一体化边缘工具 | 普通 Hough 直线检测 |

# 6. 架构约束

- 优先保留 DSPatch 执行核心以及 FlowCV 节点模型。
- UI 分组、重命名、注释不能借机更改计算图行为。
- 算法优先以现有 Node/插件接入，Qt 交互 ROI 控件放在 UI 层。
- 条件执行必须另起运行语义设计和验证，不能在阶段 A 偷偷加入。
- 假节点/占位节点必须明确未实现，不得给出伪造有效结果。

# 7. 非目标

当前阶段不追求完整复制 VisionMaster 的 UI、所有工具名称或专有算法参数，也不追求与海康 `.vm` 等格式兼容；重点是业务能力与工程执行方式的可验证实现。
